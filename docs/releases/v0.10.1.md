The Claude Code release manifest is now verified with the standard library, so
this module no longer pulls `golang.org/x/crypto` into a consumer's module graph.

claudecode:
  - The manifest's detached OpenPGP signature is checked by a small verifier
    built on `crypto/rsa` instead of `github.com/ProtonMail/go-crypto`. The
    embedded Anthropic release key is still pinned by `SigningKeyFingerprint`,
    and the signer identity is still checked. The signature must be a single v4
    RSA binary-document signature hashed with SHA-256 or stronger, dated no
    earlier than the key and not expired; SHA-1, text-mode signatures and
    unknown critical subpackets are refused.
  - `github.com/ProtonMail/go-crypto`, `github.com/cloudflare/circl`,
    `golang.org/x/crypto` and `golang.org/x/sys` leave the module graph, which
    clears the module-level `GO-2026-5932` finding in consumers' scanners.
  - The key's own expiry and revocation are not consulted; the fingerprint pin
    fixes the exact key material, and the embedded key has neither.
  - The real signed 2.1.280 manifest and its signature are committed as golden
    fixtures under `claudecode/testdata`.
